本書は、既存の要件、API、データベース、画面および運用資料を統合した初期リリースの確定要件である。本書と `basic_design.md` を、実装および受入れの基準とする。

## 2. システム概要

Famie は、家族の日々の活動を記録し、家族内で共有するモバイルファーストの Web アプリケーションである。家事、勉強、健康管理、外出などをカテゴリとともに記録し、時系列で振り返れるようにする。

スマートフォンでは PWA としてホーム画面に追加し、スタンドアロン表示で利用できる。初期リリースは家庭内利用を目的としたクローズド運用とし、許可した送信元 IP アドレスからのみアクセスを許可する。

## 3. 目的と対象範囲

### 3.1 目的

- 家族各人が日々の活動を簡潔に記録できるようにする。
- 家族全員の記録を、期間・投稿者・カテゴリで絞り込んで確認できるようにする。
- 親が家族アカウントを安全に管理できるようにする。

### 3.2 対象範囲

初期リリースの対象は、認証、家族アカウント管理、カテゴリ管理、活動ログ管理、タイムライン閲覧、PWA 化および閉域運用である。

### 3.3 対象外

以下は初期リリースの対象外とする。

- 画像・ファイル添付
- 数値記録、集計、ポイント管理
- Web Push 通知および記録リマインド
- オフライン時の投稿、下書き保存、同期
- 一般公開のサインアップ、家族外への共有

## 4. 利用者と権限

| ロール | 概要 | ログ閲覧 | ログ作成 | ログ更新・削除 | ユーザー管理 | カテゴリ管理 |
| --- | --- | --- | --- | --- | --- | --- |
| 親（`parent`） | 家族の管理者 | 全件 | 自分のログ | 全件 | 全件 | 追加 |
| 子（`child`） | 一般利用者 | 全件 | 自分のログ | 自分のログのみ | 不可 | 不可 |

ログ作成時の投稿者は、リクエストで指定せず、認証済みユーザーに固定する。親が他ユーザー名義のログを新規作成する機能は初期リリースに含めない。

## 5. 機能要件

### 5.1 アクセス制御

| ID | 要件 |
| --- | --- |
| FR-01 | Web サーバーおよびアプリケーションは、環境変数で管理する許可 IP アドレス一覧以外からのアクセスを拒否する。 |
| FR-02 | 許可 IP アドレス一覧が空の場合は、全アクセスを拒否する。 |
| FR-03 | 未認証の利用者は、ログイン以外の機能および API を利用できない。 |
| FR-04 | 一般公開のサインアップ画面および API は提供しない。 |

### 5.2 認証とアカウント

| ID | 要件 |
| --- | --- |
| FR-10 | 利用者は、ユーザー名またはメールアドレスとパスワードでログインできる。 |
| FR-11 | メールアドレスを持たない利用者を登録できる。ユーザー名は必須かつ一意、メールアドレスは任意かつ設定時は一意とする。 |
| FR-12 | ログイン済み利用者は、ログアウトできる。 |
| FR-13 | 親は、表示名、ユーザー名、メールアドレス、初期パスワード、ロールを指定して家族アカウントを作成できる。 |
| FR-14 | 親は家族アカウントの属性を編集・削除でき、本人または親はパスワードを変更またはリセットできる。 |
| FR-15 | 子は自分のパスワードを変更できるが、他者のアカウント情報を変更できない。 |

### 5.3 カテゴリ

| ID | 要件 |
| --- | --- |
| FR-20 | ログ入力時にカテゴリを 1 件選択できる。カテゴリは名称と表示色を持つ。 |
| FR-21 | ログイン済み利用者はカテゴリ一覧を取得できる。 |
| FR-22 | 親はカテゴリを追加できる。初期カテゴリは、勉強・宿題、家事・お手伝い、運動・スポーツ、習い事、健康・生活、外出・おでかけ、その他とする。 |
| FR-23 | カテゴリを削除する場合、紐づくログが存在するカテゴリは削除できない。 |

### 5.4 活動ログ

| ID | 要件 |
| --- | --- |
| FR-30 | ログには実施日、カテゴリ、活動内容を必須で登録する。実施時刻および補足メモは任意とする。 |
| FR-31 | 活動内容および補足メモはそれぞれ最大 1,000 文字とする。 |
| FR-32 | ログイン済み利用者は、家族全員のログ詳細および一覧を閲覧できる。 |
| FR-33 | 一覧は実施日の降順、同日のログは実施時刻の降順で表示する。時刻未設定のログの同日内順序は作成日時の降順とする。 |
| FR-34 | 一覧は開始日、終了日、投稿者、カテゴリで絞り込める。画面では今週、今月、指定期間を利用できる。 |
| FR-35 | 親は全ログを更新・削除できる。子は自分が作成したログだけを更新・削除できる。 |
| FR-36 | 権限のない更新・削除は拒否し、成功したように扱ってはならない。 |

### 5.5 画面と PWA

| ID | 要件 |
| --- | --- |
| FR-40 | ログイン、タイムライン、ログ作成、ログ詳細・編集、設定・ユーザー管理の画面を提供する。 |
| FR-41 | タイムラインからログ作成およびログ詳細・編集へ遷移できる。保存または削除後はタイムラインを再表示する。 |
| FR-42 | 設定画面では全利用者が自分のパスワードを変更でき、親にだけ家族アカウント管理機能を表示する。 |
| FR-43 | iOS および Android のホーム画面に追加できる PWA Manifest とアイコンを提供する。 |
| FR-44 | PWA 起動時は `standalone` 表示を利用する。オンライン接続を必須とし、オフライン投稿は扱わない。 |

### 5.6 API 契約

- API のベースパスは `/api/v1` とする。
- API は JSON を送受信し、認証済み API は Bearer Token を必要とする。
- 一覧 API はページネーションを行い、1 ページあたりの既定件数は 50 件とする。

## 6. 非機能要件

### 6.1 セキュリティ

- HTTPS を必須とし、TLS の終端は Nginx で行う。
- パスワードは Laravel のハッシュ機構で保存し、平文で保存・ログ出力・返却しない。
- API 認証は Laravel Sanctum の Personal Access Token を Bearer Token として用いる。
- 認証情報および API トークンは、通信経路で HTTPS により保護する。
- IP 制限は Nginx と Laravel ミドルウェアで二重に適用できる構成とし、リバースプロキシの信頼設定を適切に行う。
- 認可失敗は HTTP 403、未認証は HTTP 401、入力不正は HTTP 422 を返す。

### 6.2 可用性とバックアップ

- PostgreSQL データベースは定期バックアップを取得し、復元手順を運用手順として整備する。
- バックアップ頻度、保存期間、復元目標時間は本番運用開始前に運用担当者が決定する。
- アプリケーション障害時は、ログ、Nginx、PHP-FPM、PM2 および PostgreSQL の状態を確認できること。

### 6.3 利用性

- UI はモバイルを優先したレスポンシブデザインとする。
- 操作不能、入力不正、通信失敗時は、利用者が理解できる日本語のエラーメッセージを表示する。
- 主要な操作はスマートフォンの一般的な画面幅で完結できること。

## 7. データ要件

| エンティティ | 主な属性 | 制約 |
| --- | --- | --- |
| ユーザー | ユーザー名、表示名、メールアドレス、パスワード、ロール | ユーザー名は一意かつ必須。メールアドレスは任意・一意。ロールは `parent` または `child`。 |
| カテゴリ | 名称、表示色 | 名称は一意。表示色は 7 文字の Hex カラーコード。 |
| 活動ログ（`activity_logs`） | 投稿者、カテゴリ、実施日、実施時刻、内容、補足メモ | 投稿者とカテゴリは必須。実施時刻と補足メモは任意。 |

## 8. 受入基準

1. 許可されていない IP アドレスからアプリケーションおよび API にアクセスすると拒否される。
2. 親・子ともユーザー名だけでログインでき、メールアドレス未登録の子アカウントも利用できる。
3. 親はアカウントを作成、編集、削除、パスワードリセットでき、子はそれらの管理操作を実行できない。
4. ログイン済み利用者は自分のログを作成し、家族全員のログを閲覧できる。
5. 子が他者のログを更新または削除しようとすると 403 になり、親は全ログを更新・削除できる。
6. 一覧の今週、今月、指定期間、投稿者、カテゴリの絞り込みが正しい結果を返す。
7. PWA をホーム画面に追加でき、スタンドアロン表示で起動できる。
8. オフライン状態での作成・更新は要件外であり、通信エラーとして明示される。

## 9. 将来拡張

- Web Push によるリマインド
- オフライン下書き、キューイング、再同期
