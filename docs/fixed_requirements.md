Famie は、家族の日々の活動を記録し、家族内で共有するモバイルファーストの Web アプリケーションである。家事、勉強、健康管理、外出などをカテゴリとともに記録し、時系列で振り返れるようにする。

スマートフォンでは PWA としてホーム画面に追加し、スタンドアロン表示で利用できる。初期リリースは家庭内利用を目的としてIP制限した。v0.9.0では商用のみ接続元IP制限を解除し、既存アカウント認証を必須とする。ステージングのIP制限は維持する。[変更の決定](development/decisions/2026-09-28-production-ip-access.md)を参照。

## 3. 目的と対象範囲

### 3.1 目的

- 家族各人が日々の活動を簡潔に記録できるようにする。
- 家族全員の記録を、期間・投稿者・カテゴリで絞り込んで確認できるようにする。
- 親が家族アカウントを安全に管理できるようにする。

### 3.2 対象範囲

初期リリースの対象は、認証、家族アカウント管理、カテゴリ管理、活動ログ管理、タイムライン閲覧、PWA 化および閉域運用である。

### 3.3 対象外

以下は初期リリースの対象外とする。

- 画像・ファイル添付
- 数値記録、集計、ポイント管理
- Web Push 通知および記録リマインド
- オフライン時の投稿、下書き保存、同期
- 一般公開のサインアップ、家族外への共有

## 4. 利用者と権限

| ロール | 概要 | ログ閲覧 | ログ作成 | ログ更新・削除 | ユーザー管理 | カテゴリ管理 |
| --- | --- | --- | --- | --- | --- | --- |
| 親（`parent`） | 家族の管理者 | 全件 | 自分のログ | 全件 | 全件 | 追加 |
| 子（`child`） | 一般利用者 | 全件 | 自分のログ | 自分のログのみ | 不可 | 不可 |

ログ作成時の投稿者は、リクエストで指定せず、認証済みユーザーに固定する。親が他ユーザー名義のログを新規作成する機能は初期リリースに含めない。

## 5. 機能要件

### 5.1 アクセス制御

| ID | 要件 |
| --- | --- |
| FR-01 | ステージングではApacheが画面・静的ファイル・APIの全経路を、LaravelがAPIをIP制限する。許可一覧は`ALLOWED_IPS`を正本としてApacheにも同期する。商用はApacheの制限解除と`IP_RESTRICTION_ENABLED=false`で解除する。設定未指定時は制限を維持する。 |
| FR-02 | IP制限有効時に許可一覧が空の場合は、全アクセスを拒否する。 |
| FR-03 | 未認証の利用者は、ログイン以外の機能および API を利用できない。 |
| FR-04 | 一般公開のサインアップ画面および API は提供しない。 |

商用では任意のIP、ステージングでは許可IPから、ログイン前にも共通のHTML・JavaScript・CSSを取得できる。これらに家族データや認証情報を含めず、認証が必要なデータ取得・操作はLaravel APIで保護する。

### 5.2 認証とアカウント

| ID | 要件 |
| --- | --- |
| FR-10 | 利用者は、ユーザー名またはメールアドレスとパスワードでログインできる。 |
| FR-11 | メールアドレスを持たない利用者を登録できる。ユーザー名は必須かつ一意、メールアドレスは任意かつ設定時は一意とする。 |
| FR-12 | ログイン済み利用者は、ログアウトできる。 |
| FR-13 | 親は、表示名、ユーザー名、メールアドレス、初期パスワード、ロールを指定して家族アカウントを作成できる。 |
| FR-14 | 親は家族アカウントの属性を編集・削除でき、本人または親はパスワードを変更またはリセットできる。 |
| FR-15 | 子は自分のパスワードを変更できるが、他者のアカウント情報を変更できない。 |

v0.15.2 では、新規家族登録・メンバー追加・本人変更・メール再設定で設定するパスワードを15文字以上・UTF-8で72バイト以内に統一し、よく使われる語や単純な繰り返し・連番を拒否する。大文字・記号の組合せは強制せず、日本語の長いフレーズも利用できる。既存パスワードでのログインは維持し、成功時に強度を判定する。基準未達または未判定の利用者には区別して警告し、画面内で変更できる。利用者は通知を日本時間の翌日0時まで抑制できる。

ログインは同一アカウント＋IPで10分間に5回失敗すると10分停止し、IP全体も60回/分までとする（いずれもサーバー設定で調整可能）。メールとログインIDで制限を共有し、ブラウザの自己申告による端末IDは制限回避の根拠にしない。本人のパスワード変更時は現在のトークン以外を失効させる。

同一アカウントで24時間以内に上記の10分停止が2回発生した場合、その家族の有効な親全員へアプリ内通知する。IPやログイン成功の有無によらず集計し、対象アカウントごと24時間に1回まで通知する。本人の入力間違いの可能性を明示し、親がメンバー管理で対応を判断する。確認済みは親ごとに保存し、自動無効化・メール通知は行わない。

親は同一家族の自分以外の有効メンバー（他の親を含む）について、親自身の現在のパスワードによる確認後、新基準を満たすパスワードを再発行し、本人へ伝えられる。メール登録は不要。対象メンバーの全ログイン・再設定リンク・メール確認申請を失効させ、変更前のパスワードによるアカウント＋IP停止を解除する。IP全体の制限は維持する。再発行は親ユーザーごと5回/10分まで。メール未登録で他に有効な親がいない場合の本人復旧は対象外とする。

メールの追加・変更・再送は、他アカウントでの利用状況・配送成否・宛先単位の送信抑制によらず同じ受付応答と本人の確認待ち状態を返す。他人の確定済みメールには送信せず、他人のアカウントや申請を変更しない。確認待ちのアドレスは予約せず、複数の申請を認め、先に確認を完了したアカウントだけへ登録する。後続の確認は一般的なリンク無効エラーとし、登録先を上書きしない。本人の操作は60秒間隔に制限し、配送はHTTP応答後に実行する。メールには申請元ログインIDと、本人が申請した場合だけ確認する旨を記載する。

### 5.3 カテゴリ

| ID | 要件 |
| --- | --- |
| FR-20 | ログ入力時にカテゴリを 1 件選択できる。カテゴリは名称と表示色を持つ。 |
| FR-21 | ログイン済み利用者はカテゴリ一覧を取得できる。 |
| FR-22 | 親はカテゴリを追加できる。初期カテゴリは、勉強・宿題、家事・お手伝い、運動・スポーツ、習い事、健康・生活、外出・おでかけ、その他とする。 |
| FR-23 | カテゴリを削除する場合、紐づくログが存在するカテゴリは削除できない。 |

### 5.4 活動ログ

| ID | 要件 |
| --- | --- |
| FR-30 | ログには実施日、カテゴリ、活動内容を必須で登録する。実施時刻および補足メモは任意とする。 |
| FR-31 | 活動内容および補足メモはそれぞれ最大 1,000 文字とする。 |
| FR-32 | ログイン済み利用者は、家族全員のログ詳細および一覧を閲覧できる。 |
| FR-33 | 一覧は実施日の降順、同日のログは実施時刻の降順で表示する。時刻未設定のログの同日内順序は作成日時の降順とする。 |
| FR-34 | 一覧は開始日、終了日、投稿者、カテゴリで絞り込める。画面では今週、今月、指定期間を利用できる。 |
| FR-35 | 親は全ログを更新・削除できる。子は自分が作成したログだけを更新・削除できる。 |
| FR-36 | 権限のない更新・削除は拒否し、成功したように扱ってはならない。 |

### 5.5 画面と PWA

| ID | 要件 |
| --- | --- |
| FR-40 | ログイン、タイムライン、ログ作成、ログ詳細・編集、設定・ユーザー管理の画面を提供する。 |
| FR-41 | タイムラインからログ作成およびログ詳細・編集へ遷移できる。保存または削除後はタイムラインを再表示する。 |
| FR-42 | 設定画面では全利用者が自分のパスワードを変更でき、親にだけ家族アカウント管理機能を表示する。 |
| FR-43 | iOS および Android のホーム画面に追加できる PWA Manifest とアイコンを提供する。 |
| FR-44 | PWA 起動時は `standalone` 表示を利用する。オンライン接続を必須とし、オフライン投稿は扱わない。 |

### 5.6 API 契約

- API のベースパスは `/api/v1` とする。
- API は JSON を送受信し、認証済み API は Bearer Token を必要とする。
- 一覧 API はページネーションを行い、1 ページあたりの既定件数は 50 件とする。

## 6. 非機能要件

### 6.1 セキュリティ

- HTTPS を必須とし、CoreServer の Apache 構成で TLS を終端する。
- パスワードは Laravel のハッシュ機構で保存し、平文で保存・ログ出力・返却しない。
- API 認証は Laravel Sanctum の Personal Access Token を Bearer Token として用いる。
- 認証情報および API トークンは、通信経路で HTTPS により保護する。
- 制限有効環境ではAPIのIP制限をApacheとLaravelミドルウェアの二重で適用し、静的ファイルはApacheで制限する。ホスティング環境にプロキシがある場合は、信頼するプロキシを限定して送信元IPを判定する。
- 認可失敗は HTTP 403、未認証は HTTP 401、入力不正は HTTP 422 を返す。

### 6.2 可用性とバックアップ

- PostgreSQL データベースは定期バックアップを取得し、復元手順を運用手順として整備する。
- バックアップ頻度、保存期間、復元目標時間は本番運用開始前に運用担当者が決定する。
- アプリケーション障害時は、Apache・PHP・Laravel の利用可能なログ、静的ファイルと API の応答、PostgreSQL への接続状態を確認できること。

### 6.3 利用性

- UI はモバイルを優先したレスポンシブデザインとする。
- 操作不能、入力不正、通信失敗時は、利用者が理解できる日本語のエラーメッセージを表示する。
- 主要な操作はスマートフォンの一般的な画面幅で完結できること。

### 6.4 実行・配信環境

- 本番は契約中の CoreServer の Apache、PHP 8.4、PostgreSQL 14.13 を使用する。Laravel API の稼働実績がある環境を前提とする。
- フロントエンドは Nuxt 4 の SPA とし、ブラウザーで画面を描画する。ローカルの Windows 環境で静的ファイルを生成し、Apache から配信する。
- 本番サーバーでの Node.js 常駐プロセスは禁止されているため、SSR および PM2 による Nuxt の常駐運用は行わない。本番でのフロントエンドのビルドも不要とする。
- 利用者ごとのデータは実行時に Laravel API から取得し、活動ログやアカウントの変更にフロントエンドの再ビルドを必要としない。
- `/settings`、`/logs/:id` などの画面 URL は、直接アクセス・再読み込みでも利用できること。

## 7. データ要件

| エンティティ | 主な属性 | 制約 |
| --- | --- | --- |
| ユーザー | ユーザー名、表示名、メールアドレス、パスワード、ロール | ユーザー名は一意かつ必須。メールアドレスは任意・一意。ロールは `parent` または `child`。 |
| カテゴリ | 名称、表示色 | 名称は一意。表示色は 7 文字の Hex カラーコード。 |
| 活動ログ（`activity_logs`） | 投稿者、カテゴリ、実施日、実施時刻、内容、補足メモ | 投稿者とカテゴリは必須。実施時刻と補足メモは任意。 |

## 8. 受入基準

1. ステージングでは許可外IPから画面・APIへのアクセスが拒否される。商用では任意のIPからログインでき、未認証の活動データ取得・操作は拒否される。
2. 親・子ともユーザー名だけでログインでき、メールアドレス未登録の子アカウントも利用できる。
3. 親はアカウントを作成、編集、削除、パスワードリセットでき、子はそれらの管理操作を実行できない。
4. ログイン済み利用者は自分のログを作成し、家族全員のログを閲覧できる。
5. 子が他者のログを更新または削除しようとすると 403 になり、親は全ログを更新・削除できる。
6. 一覧の今週、今月、指定期間、投稿者、カテゴリの絞り込みが正しい結果を返す。
7. PWA をホーム画面に追加でき、スタンドアロン表示で起動できる。
8. オフライン状態での作成・更新は要件外であり、通信エラーとして明示される。
9. ローカルで生成したフロントエンドの静的ファイルを配置し、本番で Node.js を起動せずに主要機能を利用できる。
10. `/settings` および `/logs/:id` を直接開く・再読み込みする場合も、認証状態に応じて画面表示またはログインへの遷移が行われる。
11. IP制限有効時に許可一覧が空の場合、静的ファイルとAPIのいずれへの新規リクエストも403になる。
12. データの変更は再ビルドせず API の再取得で反映され、認証済み API の応答は Service Worker のキャッシュから返されない。
