## 結論

現在のFamieを維持したまま「米国の13歳未満は対象外」と規約に書き、単純な年齢チェックで利用を拒否するBは、採用可能と確認できなかった。Famieが一般向け・mixed audience・主として子ども向けのどの区分に当たるかを確定しない限り、このBを小規模な追加で遵守できる案として推奨しない。

前の比較では、主として子ども向けの場合の制約だけを強調し、mixed audienceでも全面排除に制約があることが不十分だったため訂正する。FTC FAQ D.6はmixed audienceでも13歳未満を参加から全面排除できないと説明する。年齢確認は子どもに必要な保護を分けるためのもので、一般向けサービスと同一の除外方法を当然に採れるわけではない。

## 公式情報と条件

| 区分・事実 | Bへの影響 |
| --- | --- |
| 一般向けサービス | FTC FAQ上、13歳未満を参加対象外とする余地はある。ただし実態に合う区分である必要があり、対象年齢を知った場合の対応も必要 |
| Mixed audience | 子ども向けサービスの一部に当たる。年齢確認で保護を分けられるが、13歳未満を全面排除するBへ直結しない。収集しない活動等を分ける可能性はあるが、Famieの認証・共有・投稿をそのまま提供する案とは別 |
| 主として子ども向け | 利用者を子どもとして扱う必要があり、単純な年齢制限で適用回避する案を採用できない |
| 国外提供元 | 日本運営・日本サーバーだけで米国の子ども向け提供/認識された収集の論点が消えるわけではない |

根拠：[FTC FAQ D.1〜D.7・国外サービス等](https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions)、[2025年改正規則のmixed audience説明・定義](https://www.govinfo.gov/content/pkg/FR-2025-04-22/html/2025-05904.htm)、[FTCの国外事業者向け説明](https://www.ftc.gov/business-guidance/blog/2018/04/where-world-warning-letters-address-geolocation-coppa-coverage)。FAQと規則の説明を区別し、分類は画面・実態・対象者等の総合判断とする。

利用者データや画像の中身は調べていない。紹介文・機能の一部を材料とした予備評価であり、法的な区分の断定ではない。

## Bを進める場合の条件付き作業

1. 現行の案内・画面・機能、想定利用者、子ども本人の操作範囲を用いて区分を確認する。一般向けと説明するために、実態と異なる文言へ置き換えない。mixed audience等に当たる可能性が残る場合は、専門的な区分確認を先に行う。
2. 一般向けとしてBを採れる場合に限り、米国との関係・年齢区分の判断方法を設計する。国籍と利用場所を同一視しない。IPだけの判定、代表者の申告だけで十分とは決めない。
3. 家族登録だけでなく、メンバー追加・初回ログイン・既存アカウント・再有効化等の経路を確認する。不要な生年月日全体の収集や、他国の子どもを一律に排除する変更は無断で追加しない。
4. 収集前の案内と制御、登録前のユーザー名確認、画像投稿、サーバーへの通信等を区別し、例外で処理できる範囲を確認する。画面チェックだけでAPIを通過できる設計にしない。
5. 対象外の利用を把握した際の停止・問い合わせ・必要な削除等の運用を定める。ログ・バックアップも含めた情報の扱いを設計する。現在の削除機能を使えば自動的に全条件を満たすとは判断しない。

## 当面の進め方

Bの調査承認をBの採用・一般向け分類の承認と読み替えない。現状ではBをリリース短縮策として確定しない。適用区分の確認後、一般向けならBの具体化、mixed audience等なら必要な子ども向け保護/機能分離または初期提供範囲の見直しを比較する。米国全体の除外等は別の方針であり、実装しない。

独立して進められるMarkdownの静的生成・版管理・代表者本人の確認機能の設計は継続可能。ただし、それらの完成をCOPPA対応済みの全世界公開承認とはしない。
