# Release CI の高速化（v0.15.2）

## 対象と計測基準

対象は `.github/workflows/release-ci.yml`。v0.15.2 の CI 高速化を先行して完了した記録である。その後の方針変更により、認証・セキュリティ強化も同じ v0.15.2 に別コミット・別PRで追加し、通常のステージング検証・商用配置を行う。

2026-10-16 に GitHub Actions の成功履歴を確認した。キュー待ちと実行時間を分け、実行時間は最初のジョブ開始から最後のジョブ完了までとする。ステップ時間は GitHub API の `startedAt` / `completedAt` の差で、秒単位の概算値。

| 改善前の run | 種別 | ジョブ実行時間 | アプリ E2E | 型チェック | クリーンビルド |
| --- | --- | --- | --- | --- | --- |
| [38816914773](https://github.com/ka215/famie/actions/runs/38816914773) | PR | 9分02秒 | 6分43秒 | 6秒 | 11秒 |
| [38803183326](https://github.com/ka215/famie/actions/runs/38803183326) | PR | 9分46秒 | 7分07秒 | 6秒 | 11秒 |
| [38804528448](https://github.com/ka215/famie/actions/runs/38804528448) | 成果物生成 | 6分50秒 | 4分58秒 | 5秒 | 8秒 |

直近 PR の依存インストールは pnpm が7秒、Composer が4秒。成果物生成 run は開始まで約7分40秒待機しており、この待機をキャッシュの効果に含めない。runner の負荷やキャッシュ状態にも差があるため、上記だけから高速化率を断定しない。

## 採用する構成

- `checks`: フロントの Lint・型チェック・単体テスト、OpenAPI 契約確認、バックエンドテスト、PostgreSQL 受入れテスト。既存の短い検証をまとめ、環境準備の重複を抑える。
- `e2e`: `chromium` / `iphone-webkit` の2ジョブを matrix で並列実行。各ジョブは対象ブラウザだけをインストールし、専用 runner 上で全テストを1 workerで実行する。DB・API・Nuxt サーバーを共有しない。片方の失敗でももう片方の結果を収集し、失敗レポート名も分離する。
- `verify`: `checks` と両 E2E の終了後、結果がすべて `success` の場合だけクリーンビルド、静的アセット確認、両ブラウザでのリリーススモークを実行する。その同じ出力から手動実行時の成果物を生成する。

ブランチ保護で必須のチェック名 `verify` を維持する。依存ジョブの失敗・キャンセル・スキップ時も `always()` で起動し、先頭の結果確認を失敗させる。依存失敗により `verify` 自体がスキップされ、必須チェックを通過することを防ぐ。GitHub はスキップしたジョブを成功扱いするため、この結果確認が必要（[公式ドキュメント](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-jobs-with-conditions)）。

並列実行により待ち時間を短縮する一方、Node・PHP・依存関係のセットアップ回数が増えるため、runner の合計使用時間は増える可能性がある。テストの省略・worker 数変更・失敗時の再試行追加は行わない。成果物の生成・昇格手順も維持する。

## 今回見送る施策

- Bun 導入: pnpm と既存 lockfile、既存 pnpm store キャッシュを継続する。
- TypeScript 増分キャッシュ: 現状5〜6秒で、Nuxt の複数 tsconfig とキャッシュ復元・保存の検証コストに対する効果が小さい。
- Nuxt・`.output` キャッシュ: ビルドは8〜11秒。検証済みの新規成果物を生成するクリーンビルドを維持する。
- Composer・ブラウザキャッシュ追加: Composer は3〜4秒で、まず支配的な E2E を改善する。ブラウザキャッシュは復元時間と OS 依存ライブラリのインストールが残るため、[Playwright 公式も通常は推奨していない](https://playwright.dev/docs/ci#caching-browsers)。

## 検証と比較

ローカルでは actionlint による workflow の静的検査、バージョン整合、両 project のテスト検出を確認する。実際の並列実行と所要時間は GitHub-hosted Linux runner 上の PR CI で確認する。改善前後ではアプリ E2E の総テスト件数とスキップ件数、リリーススモークの件数も比較する。

初回の [38840042954](https://github.com/ka215/famie/actions/runs/38840042954) では Chromium と `checks` は成功したが、WebKit の A13・A15 がタイムアウトした。トレースでは、対象者 watcher の一覧取得が先に失敗表示を描画し、初期 `/rewards/prepare` の到着前にテストがモックの回復を許可していた。そのため初期集計が成功扱いとなり、クリック前に「再試行」が消失した。失敗応答を待ってから回復を許可するよう、テストの同期を修正した。アプリの挙動、タイムアウト、リトライ設定は変更していない。修正箇所の Biome 検査と、ローカル Windows で両ブラウザ各3回、計6回の反復実行はすべて成功した。

この失敗時、`verify` は依存結果 `failure` を検出して失敗し、クリーンビルド・成果物生成を実行しなかった。必須チェックの失敗経路も実環境で確認できた。失敗 run は短縮率の比較には使用しない。

修正後の [38840882968](https://github.com/ka215/famie/actions/runs/38840882968)（コミット `dd2dc89`）は全ジョブ成功。全4ジョブで pnpm キャッシュに命中した。キャッシュ未命中時の比較は今回行っていない。

| 変更後のジョブ | 環境準備を含む実行時間 | 主な結果 |
| --- | --- | --- |
| `checks` | 1分14秒 | Lint・型・単体・API・バックエンド・PostgreSQL 検証成功 |
| `e2e (chromium, chromium)` | 3分14秒 | 79件成功・1件スキップ、E2E ステップ2分25秒 |
| `e2e (iphone-webkit, webkit)` | 5分07秒 | 79件成功・1件スキップ、E2E ステップ4分02秒 |
| `verify` | 1分38秒 | クリーンビルド・静的アセット検証成功、スモーク26件成功・2件スキップ |

最初のジョブ開始から最後の完了までは **6分49秒**。直近の改善前 PR の9分02秒に対して2分13秒、約25%短縮した。ジョブ時間の合計は **11分13秒**で、以前の9分02秒から約24%増えている。これは秒単位の実行時間の合計であり、課金上の丸めを含む請求時間ではない。アプリ E2E の成功158件・スキップ2件、スモークの成功26件・スキップ2件は改善前と一致した。

単一の成功 run と過去 run の比較であり、同一コミットでの反復測定ではない。runner 負荷、ブラウザ・OS 依存関係のインストール、キャッシュ状態によるばらつきがあるため、25%の短縮を毎回保証する値として扱わない。今後もキュー待ち、実行時間、runner 合計時間、キャッシュ命中を分けて比較する。手動実行時のリリース成果物生成は今回実行しておらず、正式なリリース準備時に確認する。
