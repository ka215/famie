# v0.20.2 詳細要件 — ギャラリーナビゲーションの表示安定化

作成日：2026-11-13（JST）。最終更新：2026-11-14。状態：商用公開・自動検証・ユーザー実機受入完了。進捗・受入の正本は[Issue #218](https://github.com/ka215/famie/issues/218)。[公開記録](../operations/change-log/2026-11-14-v0202-release-notes.md)。

## 1. 対応範囲・依存関係

元メモ1-31をR01として扱う。v0.20.1の文書閲覧・復帰の実装を前提に、ログイン直後および法務文書復帰時の固定フッターの列数変化・ギャラリー項目の後出しを解消する。リワード・アクセス解析は後続版。

## 2. 現行実装と実装順

`frontend/app/layouts/default.vue`は`galleryVisible = false`で開始し、onMountedで`GET /groups/{id}`の`images.enabled`を取得して表示を切り替える。

1. 既存の認証・家族情報・起動ローディングの取得経路を確認し、重複リクエストを避けた表示条件の共有管理へ変更する。
2. 未確定／表示／非表示／取得失敗を区別し、初期化とローディング終了条件を接続する。
3. 文書復帰、設定更新、家族切り替え、ログアウト時の再利用・破棄を実装する。
4. 低速・失敗・応答逆転を含めて検証する。

## 3. 要件

- 未確定を非表示として描画せず、表示条件が確定するまで初期ローディングを維持する。OFF確定なら3列、ON確定なら4列で初回表示する。
- 認証・同意確認の順序を維持し、必要な認可がない段階で家族APIを呼ばない。ローディング待ちが認証・同意画面を塞がない。
- 同一家族の通常画面遷移・画面を保持した文書閲覧では確定済み状態を再利用する。完全再読み込みは正規の初期化で取得し直す。
- 設定で画像機能を変更した場合は成功した値を反映する。外部端末からの変更は既存の再取得契機で追随し、常時ポーリングは追加しない。
- 状態は家族単位とし、家族切り替え・ログアウト時に破棄または再初期化する。遅い前家族の応答で現家族の表示を上書きしない。
- 通信失敗を「画像機能OFF」と断定せず、明示的な失敗表示と再試行を提供する。既存タイムアウトと整合させ、無限ローディングにしない。
- 表示条件はUI制御のみであり、ギャラリー・画像APIの認可を代替しない。API契約・DB構造の変更は原則不要。

## 6. 実装詳細（2026-11-13）

- 認証と法務同意ゲートの後、ルートミドルウェアで家族設定取得を待つ。初期起動画面を表示条件の確定まで維持し、レイアウトのマウント後の非同期切り替えを廃止する。
- `useGroupSettings`で認証トークン・所属・家族に応じた共有状態を管理。同じ所有者の取得中PromiseはNuxtアプリ単位で統合し、所有者・世代が変わった応答を破棄する。状態はアプリメモリ内のみで、ブラウザストレージには保存しない。
- 通常の画面遷移・法務モーダル復帰では確定済みの状態を利用。設定画面へ再訪した際は再取得し、既存の設定保存応答・メンバー削除後の容量再取得も共有状態へ反映する。画像機能切り替えの新しいUIは追加しない。
- メンバー削除後の再取得は成功した応答だけを共有し、失敗時は設定画面内にエラーを表示する。画面全体を再初期化せず、他の未保存入力を保持する。
- 既存のGroup型で省略可能なimagesは従来どおり無効として扱う。明示的に存在するenabledの不正型、HTTP失敗、タイムアウトは成功値のOFFへ変換しない。
- API取得は既存処理に合わせ15秒でタイムアウト、失敗時は日英のエラー・再試行・ログアウトを表示する。再試行中もログアウトでき、前の家族の遅延応答で新しい家族の表示を上書きしない。
- グループ取得中に認証失効／再同意が発生した場合もログイン／同意画面へ誘導し、起動待ちで遷移を塞がない。
