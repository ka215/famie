元メモ1-30をR01として扱う。v0.20.1〜v0.20.3を先行し、解析の判断待ちでそれらを止めない。原則はGA4のみで開始し、GTMはタグ運用の必要が確定した場合に採用する。

1. 計測対象・GA4／GTM構成・利用するプロパティ・保持期間・アクセス権・同意方針を確定する。
2. 第三者送信の台帳、日英プライバシー／Cookieポリシー、必要な法務上の取扱いを整理する。
3. ログイン状態に依存しない解析の選択・拒否・撤回を実装する。
4. 同意後のタグ読み込みと成功イベント送信、プラットフォーム区分を実装する。
5. 検証用の送信先で通信・重複・情報混入を検証し、固定候補で受入する。

## 2. 計測仕様

| 項目 | 定義 |
| --- | --- |
| login | 明示的な認証成功1回につき1イベント。失敗・二重クリック・画面再描画・トークン復元・auth/me取得では送らない |
| sign_up | 新しい家族の登録成功1回につき1イベント。メンバー追加は含めずloginとして二重計上しない |
| 利用形態 | desktop_browser／mobile_browser／pwa／unknown。standalone等で判定できるPWAを優先し、それ以外を端末情報で分類。タブレットはmobile_browserに含める |

- 初版は親アカウントと家族登録成功に絞る案を既定の提案とする。子アカウントを含む計測は別途対象・条件を確定してから実装する。未確定のまま全アカウントを対象にしない。
- 広告目的、Google Signals、User-ID、クロスデバイス照合、投稿・画像・リワード操作の詳細解析は初版に含めない。
- 氏名、家族名、ログインID、メール、家族／ユーザー／所属ID、入力値、本文、パスワード、認証情報、受付番号、問い合わせコードは送信しない。独自の永続追跡IDも追加しない。
- 自動page_view・拡張計測を含めて収集範囲を制御する。生のURL・クエリ・リファラー・文書遷移文脈から情報が漏れないよう、送信パラメータを許可リストで定義・検証する。
- 利用形態は実行状態の分類であり、インストール数・実人数の証明には使わない。GA4件数は同意拒否・ブロックで欠測する参考指標とし、全件の正確な件数が必要ならサーバー集計を別課題にする。

## 3. 同意・第三者通信

- サービスの規約同意と任意の解析選択は分ける。初期値は未同意とし、拒否しても登録・ログイン・通常利用を可能にする。
- 同意前・拒否時はGoogleの解析タグ／GTMを読み込まず、解析通信を発生させないBasic方式を採用する。拒否時にcookieless pingを送るAdvanced方式は採用しない。
- 同意UIから選択・拒否でき、後から変更・撤回できる。選択状態の保存内容・期限・版・アカウント切り替え時の扱いを文書化する。端末に同意があるだけで対象外アカウントを計測しない。
- 拒否中のイベントを蓄積し、後の同意時に遡って送信しない。撤回後の送信を止め、制御可能な解析Cookie等の削除・タグ停止方法を検証する。
- Google側のIP等の取扱いも含め、送信先・目的・保存期間・国外取扱い等の実態を確認して日英文書へ反映する。法的な適用判断を技術上の同意モードだけで代替しない。
- 現行Cookieポリシーの「外部解析SDK未導入」を導入前に改定する。既存の文書版・ハッシュ保護を維持し、同意再確認の必要性は文書改定ルールに沿って判断する。

## 4. 運用・障害時

- 計測ID・有効化設定を環境別に管理し、ローカル／ステージングが商用データへ混入しない。既定OFFで設定不備も安全に無効化する。
- タグ取得・送信失敗、広告ブロッカー、低速回線でも認証・登録・初期ローディングを待たせない。解析エラーでサービス処理を失敗させない。
- CSP・外部通信制限・PWAを確認し、必要な送信先だけを追加する。タグ導入のために広範なワイルドカード許可を増やさない。
- GTM採用時は公開権限・変更確認・許可タグを管理し、任意タグ追加で送信範囲が広がらない運用を定義する。
- 設定で解析を停止できるようにし、切り戻し時も既存の登録・ログイン・同意記録を壊さない。

## 5. 着手時に確定する事項

| ID | 判断事項 | 状態 |
| --- | --- | --- |
| P01 | GA4のみかGTM併用か | GA4のみを推奨、着手時確定 |
| P02 | 利用するプロパティ／計測ID・管理権限・保持期間 | 未設定。既存資産を確認し、不足情報のみユーザーへ確認 |
| P03 | 親のみの初期対象と、子アカウントの除外条件 | 親のみを推奨、着手時確定 |
| P04 | 解析選択の保存・期限・共有端末／家族切り替え時の扱い | 同意制御の設計時に確定 |
| P05 | 日英文書改定・対象地域・再確認の扱い | データフロー確定後に判断 |

計画承認は上記未決情報を推定して外部設定・課金契約を行う許可とはしない。確定できる実装・検証を先行し、必要情報が依存する工程だけを待機する。

## 6. 受入条件

| ID | 条件 | 検証 |
| --- | --- | --- |
| A01 | 未選択・拒否時にタグ取得／Google解析通信がなく通常利用できる | ブラウザ通信検証 |
| A02 | 同意後、対象者の成功操作に各1回送信し、自動復元・失敗・対象外では送らない | 単体・E2E・検証用GA4 |
| A03 | 撤回後に送信せず、過去の拒否中イベントを後送しない | E2E・通信検証 |
| A04 | 送信内容・自動計測・URLに禁止情報が混入しない | 通信内容検査 |
| A05 | PC／スマホブラウザ／PWA／不明を定義どおり分類する | 単体・実機 |
| A06 | 子・家族／アカウント切り替え・共有端末で対象制御が守られる | E2E |
| A07 | 無効化・通信失敗・ブロッカーでも認証／登録が成功し商用データに試験が混ざらない | 障害E2E・環境確認 |
| A08 | 日英文書・任意選択／撤回導線・設定値・運用手順が一致する | 文書検査・実機 |

変更対象Lint → 型・辞書・関連単体 → 同意と通信のE2Eを実施する。外部送信は合成データ・検証用設定で確認する。
