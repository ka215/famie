## 2. R01：モーダル背景

- 共通CSSの`dialog::backdrop`へ4pxのブラーを追加する。既存の半透明背景色、dialogの形状・位置・スクロール・フォーカス・閉じる処理は維持する。
- 登録、設定系（言語・管理・リワードを含む）、ログイン警告のネイティブdialogに適用する。画像拡大の独自オーバーレイにも同じ4px相当の背景ブラーを適用する。
- Safari向けのプレフィックスを併記する。未対応環境でも既存の背景色により表示・操作を継続できるようにする。
- リワード集中線・アニメーションはv0.18.0で対応する。

## 3. R02：ギャラリーの期間送り

- `arrow-left.svg`・`arrow-right.svg`と、タイムラインと同じ1.125remのマスク表示を再利用する。
- 操作名は既存の日英`gallery.previous`・`gallery.next`を`aria-label`で提供し、アイコンを装飾扱いにする。
- 最小44pxの操作領域、フォーカス表示、ライト／ダークの配色を設ける。
- 週／月の移動、カスタム期間での非表示、フィルター・一覧復帰を維持する。

## 4. R03：Actions更新

公式のリリース・`action.yml`を2026-10-23に確認して選定。アプリ用Node.jsは24.22.1、pnpmは11.20.0を維持する。

| Action | 変更前 | 更新先 |
| --- | --- | --- |
| actions/checkout | v4 | v7.0.1 |
| actions/setup-node | v4 | v7.1.0 |
| actions/upload-artifact | v4 | v7.0.2 |
| actions/download-artifact | v4 | v8.0.2 |
| pnpm/action-setup | v4 | v6.1.0 |
| shivammathur/setup-php | v2 | 維持（参照先はnode24） |

- すべての更新先で`runs.using: node24`を確認する。pnpmは`standalone: false`を維持し、旧Node.js内蔵バイナリへの切り替えを避ける。
- checkoutはNode.js 24にrunner 2.327.1以上が必要。コンテナ内の認証Git操作では2.329.0以上が必要だが、現行workflowは該当操作を使わない。管理下runnerはv0.17.2で2.338.1へ更新済み。GitHub-hosted runnerはGitHub側の管理とする。
- checkoutの資格情報保存先変更、setup-nodeのキャッシュ・認証関連変更、新しいartifactの非圧縮単一ファイル機能が既存経路に影響しないか確認する。
- 複数ファイルを含むZIP成果物、別runからの取得、取得後のSHA256・manifest検査、失敗時レポートを維持する。新しい非圧縮単一ファイル方式は導入しない。
- 配置・切り戻しworkflowを含めてYAML構文と既存設定の維持を確認する。ローカル検査だけでActions上の実行成功・商用配置成功とは扱わない。

公式確認先：[checkout](https://github.com/actions/checkout/releases/tag/v7.0.1)、[setup-node](https://github.com/actions/setup-node/releases/tag/v7.1.0)、[upload-artifact](https://github.com/actions/upload-artifact/releases/tag/v7.0.2)、[download-artifact](https://github.com/actions/download-artifact/releases/tag/v8.0.2)、[pnpm/action-setup](https://github.com/pnpm/action-setup/releases/tag/v6.1.0)。

## 5. 検証・公開の区切り

1. ローカル：関連Lint・型検査、既存のモーダル・画像選択・ギャラリー・日英・ダークモードのE2Eを実施。YAMLとAction定義・利用入力を確認する。
2. ユーザーのローカル確認後にコミットし、PR・CIで検証する。
3. ステージング：固定候補でiPhone Safari／PWAのブラー・画像選択キャンセル・入力保持・閉じる操作、日英の期間送りを確認する。ブラウザ自動検査と実機確認を区別する。
4. 更新したActionsによる成果物生成・取得・配置前検査を確認する。切り戻しは既存手順と互換性を確認し、実行した確認と未実施範囲を記録する。
5. 最終候補の受入と商用承認を経て、既存の同一成果物昇格手順で公開する。

表示確認の画像は`.temp/v0.17.3/`、既存E2Eのレポートは`frontend/playwright-report/`へ出力（Git管理外）。Nuxt生成では環境変数NO_COLOR／FORCE_COLOR、ビルド時間、Nitro cache-driver外部参照の警告があったが、生成・E2Eは成功した。

画像の目視確認ではChromiumのライト／ダークで背景のぼかしと前面の鮮明さを確認した。一方、Windows版Playwright WebKitでは設定値が正しくても背景がぼけない。アプリと独立した最小HTMLの通常オーバーレイ（8pxブラー）でも同じ現象を再現したため、この環境の描画結果でSafari実機のブラー合格を判定しない。原因の断定や別方式への置換は行わず、iPhone Safari／PWAで見た目・負荷を必須確認とする。

ローカルの自動検証でiPhoneのOS画像選択UIを再現済みとは扱わない。ステージングのiPhone実機確認・商用配置と切り戻し実行は別工程とし、ローカル結果から完了扱いにしない。
