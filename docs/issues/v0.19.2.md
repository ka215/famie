## 4. R01：補足メモの複数行入力

### 4.1 入力・登録動作

- 登録モーダルの補足メモだけを`textarea`へ変更。`id`、ラベルとの関連、プレースホルダー、日英辞書、入力値の保持を維持する。

- 欄内のEnterは改行とし、登録を開始しない。日本語IMEの変換確定でも登録しない。Ctrl／Cmd＋Enter等の新しい送信ショートカットは追加しない。
- 「記録する」ボタンによる登録、必須項目の検証、送信中の二重操作抑止、失敗時の入力保持、画像選択・キャンセルを維持する。
- 補足メモの省略可・最大1000文字の現行契約を維持する。改行を含めて保存し、単一行へ置換しない。HTMLとして解釈しない。
- 編集画面の初期行数は変更しない。今回入力した複数行が詳細表示・再編集でも保持されることを確認する。

### 4.2 モバイル

iPhone Safari／PWAではソフトキーボードの改行、入力欄内とモーダルのスクロール、記録ボタンへの到達、画像選択キャンセル時の入力保持を確認する。OSがリサイズハンドルを提供しない環境では手動拡張を保証せず、内容を欄内スクロールで編集できることを受入条件とする。自動伸長や専用リサイズUIは追加しない。

## 5. R02：インベントリの活動累計

### 5.1 集計定義（承認済み）

- 既存インベントリで選択中の有効メンバーについて、同じ家族内の全期間を対象にする。期間・カテゴリ・履歴ページ・リワード獲得の有無に依存しない。
- 投稿総数：対象メンバーのユーザーIDに紐づく、現在保持されている活動レコードの件数。画像数・カテゴリ数・リワード件数を数えない。対象の家族IDで必ず制限する。
- 獲得いいね総数：上記投稿に付いたいいねの件数の合計。本人が他の投稿へ付けたいいね数でも、いいねされた投稿の件数でもない。複数人からのいいねをそれぞれ1件と数える。
- 投稿といいね双方の家族IDを照合し、既存`fromActiveMembers`と同じ有効所属条件を使う。他家族・無効メンバーのいいねを混入させない。
- 投稿削除・いいね取消後は次回取得で減少する。トロフィーは従来どおり保持済みの獲得履歴を数えるため、活動の減少によって獲得済みトロフィーを取り消さない。
- 投稿0件、いいね0件はそれぞれ0。トロフィー0件でも投稿・いいねがあればその実数を表示する。

### 5.2 API契約案

`GET /api/v1/groups/{group}/rewards/awards?member_id={membership_id}&page={page}`の`meta`へ追加する。

```json
{
  "data": [],
  "current_page": 1,
  "last_page": 1,
  "total": 0,
  "meta": {
    "trophy_totals": { "gold": 0, "silver": 0, "bronze": 0 },
    "activity_totals": { "posts": 12, "likes_received": 7 }
  }
}
```

- `meta.activity_totals.posts`・`likes_received`は常に0以上の整数。既存の`total`は獲得履歴件数のままとし、投稿件数へ転用しない。
- 現行の所属・権限確認後にのみ集計する。親は有効な同一家族メンバーを選択でき、一般メンバーは本人のみ。他者指定403、他家族／存在しない／無効メンバー404の既存仕様を維持する。
- DBで集計し、全投稿・全いいねをPHPやブラウザにロードしない。結合により投稿数がいいね件数分だけ水増しされない方式を使う。集計クエリ数は一覧件数に比例させない。
- 新しいDBカラム・保存済みカウンター・マイグレーションは予定しない。既存索引と取得計画を確認し、DB変更が必要になった場合は理由と影響を提示して再判断する。
- OpenAPI、獲得一覧専用の型、実API契約検査を同時更新する。管理・進捗・通知APIの応答へ広げない。
- 投稿・いいねの同時変更に対する厳密な全集計の時点一致は保証しない。再取得時に現状へ追随し、集計のために長い排他ロックを追加しない。

### 5.3 表示・アクセシビリティ

- 現行の非カード累計行を拡張し、`金 N | 銀 N | 銅 N | 投稿アイコン N | いいねアイコン N`の順にする。
- 投稿は指定`chat-processing-outline`のSVG・青系、獲得いいねは指定`hand-heart-outline`のSVG・ピンク寄りの赤を使用する。既存ファイルが同一SVGなら再利用する。
- 5指標の間は縦線で区切る。区切りとアイコンは装飾扱いとし、各項目に「アクティビティ投稿総数 N件」「いいね獲得総数 N件」相当の日英読み上げ名を付ける。累計行のグループ名も追加内容へ合わせる。
- 既存のロケールに応じた整数フォーマットを再利用する。読み込み中・エラー時は0と断定せず`—`。色だけで意味を区別しない。
- 320px幅や大きな数値は累計行内の横スクロールで表示し、指標を欠落させない。タッチとキーボードで全指標へ到達でき、ページ全体の横はみ出しがないことを確認する。

### 5.4 再取得・状態管理

- 初期選択は本人。親のメンバー変更時は5指標をすぐ未確定表示に戻す。一覧・トロフィー・活動累計を検証後まとめて反映する。
- 非負の安全な整数と必須キーを検証。不正応答や通信失敗は既存エラー・再試行で扱い、古い数値や0を成功値として表示しない。
- 世代管理・画面離脱・家族変更・ログアウト時の破棄を維持する。遅い応答で前メンバーの数値を再表示しない。
- ページ送りや既存の再取得・画面再訪で更新する。常時ポーリング、新しい更新ボタン、いいね送受信のリアルタイム同期は追加しない。
