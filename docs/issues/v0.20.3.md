# v0.20.3 詳細要件 — リワードの名称・説明・対象者を即時反映

作成日：2026-11-13（JST）。最終更新：2026-11-14。状態：最新devから作成した`feature/v0.20.3`でローカル実装・関連自動検証完了、2026-11-14ユーザーローカル確認合格。PR・ステージング準備中、商用未公開。進捗・受入の正本は[Issue #223](https://github.com/ka215/famie/issues/223)。

## 1. 対応範囲と影響

元メモ1-23をR01とする。名称・報酬の説明・対象者のみ、開始済みで有効なリワードへ即時適用する。他の項目は既存の次サイクル適用を維持する。

現行`RewardController::update`は開始済みの編集を次サイクルのRewardVersionへ一括保存する。対象者はRewardTargetとして版に紐づき、`RewardService`の進捗集計・対象リワード一覧・獲得判定に使われる。獲得済みRewardAwardはスナップショットを持つ。影響度は中程度で、表示だけの修正ではない。

## 2. 仕様

### 2.1 現在版・予約版

- 名称・説明・対象者は現在の版へ反映する。予約済みの次サイクル版がある場合も同じ3項目を反映し、次回に古い値へ戻らないようにする。
- 同時に編集した獲得条件・色などは次サイクル版だけへ保存する。3項目だけの編集で、予約済み条件を現在の条件へ巻き戻さない。
- 予約版の存在だけで「条件変更予約あり」と誤表示しない。現在値・予約値・保存結果をAPI型とUIで整合させる。
- 下書き・開始前は既存の全項目変更方式を維持する。停止中の開始済みリワードは3項目の変更を保存しても付与処理を実行せず、再開時の既存評価へ接続する。停止中の編集でも獲得条件の次サイクル適用は維持する。
- 過去サイクルの版・獲得済みスナップショットを変更しない。現行版が過去期間から継続している場合は、過去版を直接書き換えず現在サイクル境界で分離する方式を優先する。必要なデータ構造変更は着手時の調査で理由・移行・切り戻しを明記する。

### 2.2 対象者の追加・除外

- 対象は既存と同じ有効な同一家族メンバーのみ。管理権限・有効数制限・家族IDの検証を維持する。
- 追加時は現在サイクル内の既存実績も含め、現在の獲得条件で即時再集計する。参加後だけの集計や参加日時カラムは追加しない。
- 既に達成していれば保存時に付与する。画面表示・通知は既存の獲得通知経路で扱い、同一期間・同一メンバーに重複付与しない。
- 対象外にしたメンバーは現在の対象一覧・未達進捗表示から除外する。獲得済みトロフィー・履歴・通知の既存保持仕様は維持する。
- 同一サイクル内の除外→再追加でも既存獲得を保持し、二重付与しない。未達者は再追加時点の実績で再評価する。
- 家族の新規メンバー登録そのものでは全リワードへ自動参加させず、対象者編集で追加可能にする。

### 2.3 整合性・画面

- 現在版・予約版・対象者・revision更新と必要な再評価を既存の家族書込トランザクション／排他規約に揃える。途中失敗は全体をロールバックする。
- 同時編集のrevision不一致、活動投稿・いいね・サイクル準備との競合で更新喪失・重複付与を起こさない。応答は更新後の現在版・予約版を返す。
- 編集フォームの3項目のラベル横に「即時反映」バッジを日英で表示する。色だけで意味を表さない。
- 注意文は「名称・報酬の説明・対象者はすぐに反映されます。その他の変更は次サイクルから適用されます。獲得済みトロフィーは維持されます。」相当とする。新規作成・開始前など状況に応じて誤解のない表示にする。

## 3. 実装順と対象

1. 版の分離・更新、予約条件の保持、権限・排他の設計を既存仕様と照合する。
2. RewardController／RewardService／必要最小限のモデル処理を変更し、関連PHP・PostgreSQL試験で保証する。
3. API応答・OpenAPI・共有型・編集ダイアログ・日英辞書を揃える。
4. E2E、ローカル確認、固定候補のステージング確認を行う。

新しい集計方式・定期ジョブ・他者閲覧権限の拡張・トロフィーフィルターは対象外。

## 6. 実装詳細（2026-11-14）

- 開始済みの有効／停止中リワードは現在サイクル開始日をeffective_fromとして現在版を更新する。元版が前のサイクルから継続していれば同日付の新しい版を作成し、過去版を保持する。現在サイクル内の再編集はその版を更新する。獲得済みスナップショット・過去期間・既存獲得は書き換えない。
- 名称・説明・対象者を現在版と予約版へ反映し、現在の獲得条件を維持する。新たに条件を変更した場合は次サイクルへ予約する。即時項目だけの更新では新しい予約を作らず、条件差のない旧予約は編集時に整理する。
- 更新入力に任意booleanのupdate_conditionsを追加。falseなら既存予約条件を保持、trueなら送信条件に変更する（現在条件と同じなら予約取消）。省略時は現在条件との差分で判定する。フォームは開いた時点の予約版優先の条件と比較し、条件を変更した時だけtrueを送る。これにより予約済みの条件を維持した再編集と、現在条件への意図的な取消を区別する。
- 対象者を除外した場合は現在サイクルの未達進捗キャッシュから除外する。過去進捗・獲得・通知は保持する。有効リワードは現在条件と当サイクルの既存実績で即時再評価し、既存の一意制約と通知経路で1回だけ付与する。停止中は保存だけで付与せず、既存の再開時評価へ接続する。
- 下書き・開始前は従来の全項目即時更新を維持する。既存の家族書込トランザクション／行ロックを利用し、版・対象者・revision・付与の途中失敗は全体をロールバックする。権限・有効メンバー・同一家族・有効数制限は既存規約を維持する。
- 開始済み編集時だけ3項目に日英の即時反映バッジを表示する。名称・説明の入力欄はaria-labelで名称を維持し、バッジ追加後も入力ラベルで操作できる。新規・下書き・開始前は既存ガイダンスを維持する。
- OpenAPIと共有RewardInput型を更新。応答の現在版／予約版の形は維持する。DB構造変更・migration・既存データの一括更新は不要。既存版モデルの範囲で追加されるため、切り戻しにDB復元は不要（旧版では編集が再び次サイクル一括適用になる）。
