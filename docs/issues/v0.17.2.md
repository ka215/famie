# v0.17.2 詳細仕様 — Node.js・ローカルPHPセキュリティ更新

作成日：2026-10-22。作業ブランチ：`feature/v0.17.2`（最新devから分岐）。

状態：**2026-10-23商用公開・ユーザー実機確認合格**。最新の受入・公開記録は7章を参照。

ユーザーから緊急対応の実施指示を受領。Node.js 24.19.0から24.22.1へ更新する。26系へのメジャーアップグレードは行わず、既存の24系LTSを維持する。pnpm内蔵ランタイム対策も追加承認済み。ローカル確認OK後にコミット・ステージングへ進み、商用リリース承認は別途受領する。

## 1. 背景・対象

[公式セキュリティ告知](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)と[24.22.1リリース情報](https://nodejs.org/en/blog/release/v24.22.1)で修正版を確認した。TLS・DNS・Brotli等の修正を含む。今回のコード経路で各脆弱性を悪用できるかは断定せず、利用ランタイムを修正版へ更新する。

| 対象 | 対応 |
| --- | --- |
| ローカルの通常node | pnpm管理のNode.jsを24.22.1へ更新 |
| ローカルのpnpm | 11.20.0を維持。Node.js 26.0.0内蔵の@pnpm/exeから、通常node 24.22.1で実行するJavaScript版へ切替 |
| Release CI | checks・E2E・verifyの3箇所を24.22.1へ更新 |
| 配置後のブラウザテスト | deploy-releaseの指定を24.22.1へ更新 |
| CIのpnpm | 11.20.0を維持し、standalone=falseを明示。内蔵Node.js付き@pnpm/exeを使用しない |
| 開発環境の案内 | .node-versionへ24.22.1を記載し、開発ガイドを更新 |
| 版情報 | current=0.17.1を保持、next=0.17.2。packageの版は既存のリリース準備スクリプトで更新 |

商用サーバーはApacheによる静的SPA配信とPHP APIで、Node.jsを常駐実行しない。Node.jsの更新だけで公開中の静的ファイルにサーバー側Node.jsランタイムが追加・変更されることはない。更新環境で再生成・検証した固定成果物を通常のリリース工程で配置する。アプリ機能・DB・API・frontend依存パッケージ・lockfile・pnpmの版は変更しない。

## 2. 別管理ランタイムの確認と残事項

actions/setup-nodeの指定はビルドやコマンドに使うnodeを切り替えるもので、JavaScript Actionsを起動するrunner内蔵Node.jsは更新しない。Actionのメジャー版を変えるだけでも、内蔵Node.jsのパッチ版は保証されない。

2026-10-22の確認時、ローカルself-hosted runnerのexternals/node24は24.19.0、node20は20.20.2で、runnerはofflineだった。公式最新リリースv2.338.0のソースはNode.js 24.21.0を指定していた一方、開発中mainは24.22.1へ更新済みだった。

- [runner v2.338.0の外部ランタイム指定](https://github.com/actions/runner/blob/v2.338.0/src/Misc/externals.sh)
- [runner最新リリース](https://github.com/actions/runner/releases/latest)

上記は初回調査時点の状況。ローカル動確OK後の再確認で、2026-10-22にNode.js 24.22.1同梱の公式runner v2.338.1が公開されたことを確認した。SHA256照合済み公式配布物で停止中のself-hosted runnerを2.337.0から2.338.1へ更新し、内蔵node24も24.22.1と確認。旧bin・externalsと起動ファイルはC:\actions-runner-famie配下の*.before-v2.338.1へ退避し、登録情報を維持した。配布物SHA256は`478f533ac2c349040fbaea7e158f7f7d0235085cf35bc81f661af0c715207ff9`。

- [runner v2.338.1](https://github.com/actions/runner/releases/tag/v2.338.1)
- [同梱ランタイム指定](https://github.com/actions/runner/blob/v2.338.1/src/Misc/externals.sh)

self-hosted runnerのnode24未更新は解消した。node20は公式配布物に残るが、Node 24へ移行した内部処理と通常のActions実行では使用しない。旧Nodeへ戻す環境設定は追加しない。GitHub-hosted runnerはGitHub側が管理するため、本変更で全ホストの内蔵ランタイム更新を保証するものではない。

旧@pnpm/exeはローカルの旧インストール領域に残るが、pnpm／pnpxの起動経路はJavaScript版へ切り替える。起動ファイルをGit管理外の.tempへバックアップし、通常のnodeとpnpmの実行経路を確認する。旧バージョンのディレクトリや他のグローバルツールは削除しない。

## 5. 追加依頼：ローカルPHP更新・切替環境整備

ユーザーの実施依頼により、php2shell対応版PHP 8.2.35／8.3.36／8.4.27／8.5.12をローカルXAMPPへ追加した。[PHP公式セキュリティ告知](https://www.php.net/archive/2026.php#2026-10-21-5)を参照。Famieの標準は商用と同じ8.4.27とし、8.2でFamieアプリを起動する用途には使用しない。

### 5.1 サーバー確認結果

ユーザーがWeb経由で確認した商用famie.coとステージングstg-famie.ka2.orgはHTTP 200、PHP 8.4.27、cgi-fcgiだった。旧famie.ka2.orgはHTTP 302で、転送元PHPの版自体は未確認。共有サーバーのPHP変更は今回実施していない。

確認用のLinuxシェル`check-web-php.sh`を追加した。対象FQDNと公開パスを配列で設定し、~/test/helthcheck.phpへの一時リンクを作成・HTTPS確認・削除してTSVへ記録する。通常終了と捕捉可能な中断ではcleanupし、既存ファイルを上書きしない。強制終了・サーバー停止時は自動cleanupを保証できない。ユーザーの実行結果は上記のとおり。

### 5.2 ローカル変更

- PHP公式のx64 TS ZIPとImagick公式3.8.1の系列別TS DLLを取得し、配布元SHA256と照合。
- C:\xampp\php8.2.35／php8.3.36／php8.4.27／php8.5.12を作成。PHP同梱拡張は新版を使用し、Imagickと依存DLLを追加。
- 8.2設定は旧8.2.12、8.4設定は旧8.4.24を引継ぎ。新設8.3と設定未作成だった8.5は既存8.4のローカル設定を基に準備し、各版の起動・拡張・Web応答を検査。extension_dirとログは系列ごとの実パスにした。
- Apacheは現在の構成を各apache8.x.xxへ複製し、VirtualHost・プロキシ・証明書設定を維持。OpenSSLのDLLは各PHP同梱版に揃えた。Apache本体の更新ではない。
- C:\xampp\chphp.batを更新し、C:\xampp\chphp.ps1へ処理を分離。4版の選択、準備検査、Apache停止、リンク退避、切替、設定検査、再起動を実装。失敗時は元のリンクへ復旧する。-Version指定と-CheckOnlyも利用可能。
- シンボリックリンク新規作成には現在の権限が不足するため、切替先はディレクトリジャンクションとした。既存リンクと実体フォルダは削除せず、旧リンクをC:\xampp\.chphp-日時-*へ退避する。XAMPP外のリンクや実体ディレクトリを切替対象にしない。
- 元のバッチ・PHP設定・稼働Apache設定とダウンロード照合結果をC:\xampp\security-update-backups\20261022-php2shellへ保存。

### 5.3 確認結果・注意点

4種類すべてでCLI版・x64 TS・Apache設定検査・Apache再起動・Web側PHP版・apache2handler・HTTP 200・ImagickのWebP生成に成功した。8.2のPDOは従来同様mysql／sqlite、他3版はmysql／pgsql／sqlite。最終的にPHP 8.4.27へ戻し、Famieの/api/v1/statusがHTTP 200・status=ok、Composerのplatform requirements成功を確認した。一時確認PHPは公開パスから退避済み。

実行結果は上記バックアップ先のweb-verification.txt、照合記録はdownload-checksums.tsvを参照。PHP・Apacheの外部環境ファイルはFamieのGit管理へ追加しない。更新バッチはPowerShell 7が必要で、起動中のApacheは再起動し、停止中なら停止状態を維持する。

既存Apache 2.4.58には、更新前からmod_sslのビルド時OpenSSL版と実行時ライブラリの不一致警告、およびデフォルト証明書名の警告がある。今回はApache本体・TLS構成を再設計していないため、この既存警告は別対応事項として残る。ローカルHTTPのFamie API・PHP版・画像処理の確認は成功している。

Laravelの既存composer testはPHP 8.4.27で成功（全302件、265成功・37スキップ、1909 assertions）。PostgreSQL専用等の環境条件付きスキップを含む。アプリコード・DB・vendorには変更を加えていない。

旧バッチのバックアップは、更新版の保存先重複で上書きされたため、作業前に読み取った内容から復元した控えとした。更新版はchphp-updated.batとして分けて保存済み。旧PHP・Apache実体と旧設定バックアップは保持している。
