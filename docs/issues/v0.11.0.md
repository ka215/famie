# v0.11.0 詳細要件 — 家族管理と表示設定

2026-10-03、対象を課題5・11-A・25に確定。作業ブランチは`feature/v0.11.0`。

## 目的・対象範囲

設定画面からメンバーの編集・無効化・復元、カテゴリの編集・削除、端末ごとの表示テーマ選択を行えるようにする。v0.10.0の家族分離・所属状態・履歴保持を引き継ぎ、DBスキーマと依存パッケージは変更しない。

メール追加・変更・認証とパスワード再発行は次版候補。カテゴリ並び替え、ログインID変更、他者の資格情報変更、物理的なメンバー削除、複数所属・招待・移籍、リワード、画像は対象外。

## メンバー管理（課題5）

### 画面・入力

- 既存の「家族メンバー」カードはactiveのみ表示し、adminに管理ボタンを表示する。memberは閲覧のみ。
- 管理ダイアログで表示名（前後空白除去後1〜50文字）と役割（admin／member、表示は親／子）を編集する。ログインIDは参照のみ。メールやパスワードは表示・編集しない。
- 自分の表示名も編集可能。自分の役割変更と無効化は不可とし、理由を表示する。最後のactive adminを失う操作をサーバーでも拒否する。
- 無効化は確認を挟み、ログインできなくなることと、既存の活動記録が全員の画面から非表示になることを説明する。
- admin専用の「無効化済みメンバーを復元」を通常一覧と分けて設け、必要時に一覧を取得する。対象者の表示名・ログインID・役割を示し、確認後に復元する。inactive中の編集は提供せず、復元後に編集する。
- 復元時は人数上限（既存設定、初期10人）を再確認する。上限超過は理由を表示して拒否する。
- 更新成功後に一覧を再取得し、自分の表示名を変更した場合は本人情報も更新する。再取得失敗は保存失敗と区別して再読み込みを案内する。
- 二重送信を抑止し、送信中は閉じる操作を抑止する。キャンセルでは更新しない。エラーはダイアログ内に表示し、入力を保持する。

### API

すべて`/v1`配下。変更対象の識別子はユーザーIDではなく`membership_id`。

| API | 権限・入力・応答 |
|---|---|
| GET `/groups/{group}/members` | 既存のactive一覧を維持 |
| GET `/groups/{group}/members/inactive` | adminのみ。inactive一覧、メールなし |
| PATCH `/groups/{group}/members/{member}` | adminのみ。`display_name`・`role`の両方を必須とし、その他のキーを拒否。active対象のみ |
| PUT `/groups/{group}/members/{member}/status` | adminのみ。`status`（active／inactive）のみ必須。既存サービスを利用 |

一覧・更新応答のメンバーは`id`（user ID）、`membership_id`、`username`、`display_name`、`role`。状態変更は`status`も返す。認証用メール、password、tokenを返さない。書き込み応答は既存どおり`message`・`data`。

未認証401、同一家族の権限不足403、別家族・存在しない対象404、入力・自己保護・上限違反422。無効化済み対象への編集は422。同一状態への再要求はデータを壊さず、無効化時のtoken失効も維持する。

### 整合性・認可

- ユーザー・所属・活動記録・識別子を保持する。inactive投稿者の記録は一覧・件数・詳細・絞り込みで非表示、復元すると同じIDの記録を再表示する。
- 無効化で全tokenを失効し、復元しても旧tokenは復活させない。再ログインが必要。
- 家族への書き込みは家族行をロックしてactive所属・権限を再確認し、無効化・降格・復元・メンバー作成・活動保存・カテゴリ削除を同一家族内で直列化する。ロック順は家族→所属→対象データ。
- ログインの所属確認とtoken発行も同じ家族ロックで保護し、無効化と競合してtokenが残らないようにする。本人情報・パスワードの更新も所属無効化との競合から保護する。
- 他adminに降格された利用者の次の管理要求は拒否する。画面の表示権限だけに依存しない。

## カテゴリ管理（課題11-A）

- adminはカテゴリバッヂから管理ダイアログを開ける。memberのバッヂは閲覧用のまま。
- 名前（前後空白除去後1〜255文字、同一家族内で一意）・色（`#RRGGBB`）を編集する。既存APIのnullable色は維持し、未指定の既存カテゴリはUIで既存の標準色を初期表示する。
- 名前・色は過去の活動表示にも反映される旨を表示する。
- 削除は確認を挟む。活動記録から未参照の場合のみ削除でき、inactive投稿者の非表示履歴からの参照も削除不可とする。
- 使用中、同名、権限不足、通信失敗の理由を表示する。削除判定はAPIを正本とし、活動登録との競合を家族ロックで保護する。
- 既存のPUT・DELETE `/groups/{group}/categories/{category}`を使用する。並び順は変更しない。保存・削除後は一覧を再取得する。

## 表示設定（課題25）

- 全ロールに「表示設定」カードを追加する。選択肢はライト／ダークの2択で、選択直後に反映し、保存ボタンは置かない。
- `localStorage`の`famie-theme`へ`light`または`dark`を保存する。同じ保存領域内でログアウト・ユーザー切り替え後も保持し、端末間同期はしない。Safariとホーム画面PWAで保存領域が異なる場合は各々設定する。
- 未設定・不正な保存値の場合のみ起動時のOS設定を読み、初期値として保存する。OS変更への継続追従はしない。保存領域を消去すると初期化される。
- 保存不可の場合も現在の画面で選択でき、永続化できなかった旨を表示する。再起動時は再び初期値から開始する。
- 初回描画前にテーマを適用する共通スクリプトを使用し、Nuxt画面・起動画面・静的メンテナンス画面で同じ値を使用する。
- Tailwindの`dark:`、全体CSS、カレンダーの独自CSS、`color-scheme`、`theme-color`を同じテーマへ揃える。PWAのOS起動スプラッシュはmanifestの静的色であり、アプリ描画以降を切り替え対象とする。
- ログイン・登録・設定・タイムライン・活動モーダル・編集・メンテナンスで選択が継続する。同一保存領域の別タブの変更も反映する。
