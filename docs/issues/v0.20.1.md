## 2. 現行実装と対応方針

- 文書は`frontend/scripts/legal-page.mjs`で静的HTMLを生成する。JavaScript・認証APIなしの閲覧を維持する。
- `frontend/public/legal-page.js`の戻り先は現在login/settingsのみ。`LegalConsentFields.vue`のリンクには戻り先がない。
- 登録フォームは`register.vue`内のrefで管理され、静的ページへの遷移で破棄される。
- `LegalLinks.vue`、`LegalConsentFields.vue`、静的文書のリンク処理を共通方針に揃える。既存の文書版・言語・テーマ・認証ゲートを維持する。

## 3. R01・R02：文書閲覧と復帰

- アプリからは元画面を保持した文書閲覧を第一候補とする。同一タブの閲覧UIで、登録フォームを破棄せず、閉じる操作・「元のページへ戻る」で入力済みの全項目を復元する。パスワードと確認欄も対象。
- 文書間リンク、プライバシー→Cookie、日英切り替えを経ても最初の遷移元を維持する。ブラウザの戻る操作も確認する。
- 戻り先はlogin/register/settings/legal-confirmationなどの許可済み識別子とし、任意URL・外部リファラーを遷移先にしない。不正・欠落時は安全な既定先へ戻す。
- フォーム値は当該画面のメモリ内に保持する。URL、localStorage、sessionStorage、ログへ保存しない。通常の再読み込み・タブ終了後の復元は保証しない。登録完了・画面離脱時は不要な状態を破棄する。
- 文書閲覧を同意とみなさず、自動チェックしない。保持済みチェックは文書版が同一の場合のみ有効とし、版変更時は既存の再確認処理に従う。
- ログイン復帰時にはID・パスワード欄へ自動フォーカスさせない。操作元リンクなど非入力要素へのフォーカス復帰でキーボード操作を維持する。通常ログイン時の操作を阻害しない。
- 直接URL・JavaScript無効時の静的文書閲覧を維持する。閲覧UIが開けない場合のリンク動作も用意する。iframeを採用する場合はタイトル、スクロール、フォーカス移動、Esc、背景操作抑止と同一オリジンの通信検証を確認する。
- この方式でPWAの戻る・入力保持が満たせない場合、実装結果と代案を提示する。秘密情報の永続保存で解決しない。

## 4. R03〜R07：画面要件

- R03：登録画面末尾の`HomeInstallGuide`と`LegalLinks`を削除する。同意欄内の規約・プライバシーリンク、ログインへ戻るリンクは維持。ログイン画面のガイダンスと3文書リンクは維持する。
- R04：受付番号はAPIのUUID形式、確認コードは`[A-Za-z0-9_-]`の43文字に合わせる。双方が有効で照会中でない場合のみ送信可能。submit処理と記憶済み値による自動照会にも同じガードを使う。書式不正を「受付なし」と扱わず、サーバー側検証・レート制限を維持する。確認コードをURLやログへ出さない。
- R05：`legal-confirmation.vue`の言語切り替えボタンだけを削除する。アカウント言語による表示、ログイン・登録画面や文書自体の言語切り替えは維持する。
- R06：設定の3文書リンクを利用規約→プライバシー→Cookieの順で、左揃え・縦3行表示にする。ログイン側の配置は変えない。
- R07：「利用ライブラリのライセンス」はアプリ内専用カード画面へ遷移する。`THIRD_PARTY_NOTICES.txt`を正本として全文をエスケープ表示し、手動コピーを増やさない。言語切り替えなし、設定への復帰、長文・長いURLの折返し、ライト／ダーク、取得失敗時の再試行を備える。直接テキストURLは残す。認証・同意ゲートは通常の設定関連画面と揃える。
- 追加するユーザー向け文言は日英対応する。ライセンス原文の翻訳は行わない。

## 7. ローカル実装・検証記録（2026-11-13）

- `LegalDocumentLink.vue`で既存SettingsDialogと同一オリジンの静的文書iframeを組み合わせ、元フォームをメモリ内で保持する。文書の「元のページへ戻る」、閉じる、Esc、ブラウザの戻るで復帰する。
- 静的文書側は許可済み戻り先を継承する。埋め込み時の文書・言語遷移はiframeの履歴を置換し、元画面へ戻れる履歴を維持する。閉じる通知はoriginと送信元frameを照合する。
- 登録末尾のガイダンス・法務ナビ、同意画面の言語ボタンを削除。設定法務リンクを3行化し、ライセンスの全文表示・再試行画面を追加した。
- 退会照会にUUID／43文字コードの判定とsubmit・自動照会のガードを追加した。
- 変更対象Biome、型チェック、辞書検査、法務単体6件は合格。静的生成も合格した。既存出力削除が自動承認レビューで拒否されたため、`.temp/v0201-build/output-2/public`へ隔離生成し、既存`.output`を保持した。
- Chromium／iPhone相当WebKitの関連release試験は18ケース。初回16件合格、ライセンスのテスト側期待値を修正し、対象2件の再実行で合格した。実装の再変更・再ビルドは不要だった。取得失敗→再試行→正本全文一致も確認した。
- PWA制御下の静的文書閲覧とWebKitでの復帰は自動確認済み。実機のキーボード表示・スクロール・既存PWAキャッシュ保持、320px幅を含む最終表示確認はユーザー確認・ステージング受入で実施する。

ローカル確認対象は、ログインで文書を開いて戻る、登録の全項目を入力してプライバシー→言語切り替え→Cookie→復帰、照会フォームの入力可否、設定の3文書とライセンス画面。同意確認画面は再同意が必要なアカウントで言語ボタンがないことを確認する。実機受入前に各フェーズを完了扱いにしない。

ローカル確認中の追加対応：埋め込み文書は専用の表示属性でカード背景・影・角丸・外側余白を解除し、単独閲覧のカードは維持した。文書再生成・関連Lint・単体6件に合格。また、ローカルの同意欄非表示は既存の機能フラグ2件がfalseで、同意履歴テーブルが未作成だったことを確認した。APP_ENV=localを確認して既存の同意履歴マイグレーションだけを適用し、ローカル.envのstorage／acceptanceをtrue、設定キャッシュをクリアした。開発画面が参照する実HTTP APIでacceptance_enabled=true・文書3件を確認した。登録UIの同意要件を緩めるコード変更は行っていない。

追加のユーザー指定により、モーダル内では文書側のh1・言語切り替えを非表示とし、外側で選択した言語を継承する。モーダルヘッダーのタイトルは1.25rem・行高1.4とし、プライバシー→Cookieなど文書間移動時も表示中の文書タイトルへ追随する。単独ページのタイトル・言語切り替えは維持する。以後、埋め込み文書内の言語変更は受入条件から除外し、外側の言語選択と継承を確認する。

最終修正後は変更対象Lint、法務単体6件、隔離した静的生成、Chromium／iPhone相当WebKitの文書閲覧・登録復帰・設定導線の6ケースに合格。ユーザーのローカル確認合格を受領した。この承認は商用リリース承認ではない。

PR #214の初回CIでは通常アプリE2Eを含む各検査は通過したが、WebKitの永続レート制限付きライフサイクル試験が、家族設定を開けず退会ボタン待機でタイムアウトした。失敗時の画面・ログを確認し、当該試験の見出し文字へのタップをsummaryへのフォーカス・Enterとopen属性確認へ置き換えた。アプリ本体は変更していない。ローカルの隔離E2E環境で同じ永続レート制限を有効にし、WebKitの対象2件が合格した。試験プロセス内の法務フラグは従来CIと同じfalseとし、開発用.envの有効設定は維持した。修正後のCIで改めて必須gateの合格を確認する。

2回目のCIではsummaryの開閉は通過したが、その直後の退会ボタンのタップ後にdialogがなく、警告待機で失敗した。取得した画面記録でレート制限の警告以前にモーダルが開いていないことを確認し、同じ試験の退会ボタン操作もフォーカス・Enterとdialog表示確認に統一した。ローカルWebKit・永続レート制限ありの2件を再実行して合格した。UIのタップ回帰は通常アプリE2Eの検証を維持し、当該試験ではレート制限の検証を確実に行う。
