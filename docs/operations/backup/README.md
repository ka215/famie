# バックアップ管理

[台帳保全の継続運用は後続課題 #200へ移管](https://github.com/ka215/famie/issues/200)。具体的検討はv1.0.0以降、自動化は管理画面構築後に検討する。v0.20.0の進行条件にしない。以下は単発検証の記録であり、ステージングの定期取得や追加USB保存は要求しない。

実際の操作は[鍵予備のUSB保存・別PC確認手順](f03-usb-key-check.md)を参照する。PCごとの入力コマンド、成功時の表示、失敗時の停止箇所を記載している。

続く[ステージング台帳のUSB保存・別PC照合手順](f03-usb-ledger-check.md)も用意した。現時点の台帳1件のコピーとハッシュ照合を対象とし、同期記録v2の業務検証・商用台帳・実DB復旧とは区別する。

2026-11-06、運営者が台帳手順1〜4の成功を報告し、対象時点のステージング台帳のUSB保存・別PC照合まで完了した。自動同期は行わず、後続の退会・削除記録はこのコピーへ自動反映されない。

PostgreSQL のバックアップ方針、保存先、保持期間、実施記録、復元検証を管理する。

復元検証には、使用したバックアップ、復元先、結果、実施日時、実施者を記録する。バックアップデータ本体や認証情報はリポジトリに保存しない。

F03のUSB・別端末での鍵予備確認は[実媒体・鍵予備・通知の確認準備](../../development/account-lifecycle-implementation-plan.md#1020-f03実媒体鍵予備通知の確認準備2026-11-06)を参照する。元鍵を保持し、暗号化予備のハッシュと別端末での開封を別々に記録する。2026-11-06に運営者がステージング用鍵の予備作成・USBコピー照合・別PCでの開封を確認した。商用鍵・台帳の別媒体保存・実データ復旧の合格を意味しない。実DBバックアップは変更していない。
