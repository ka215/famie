# 台帳保全の継続運用：後続版へ移管

2026-11-07の運営者指示により、継続運用の具体的検討はv1.0.0以降の後続版で扱う。自動化は管理画面の構築後に検討する。v1.0.0公開時の実装・稼働条件には追加しない。

## v0.20.0で行わないこと

- 保存先の契約・バケット・認証情報の作成。
- 自動転送・定期差分確認・失敗/欠測通知の実装と運用。
- 周期・許容遅延・料金・処理時間・保持ロックの詳細設計や実測。
- ステージング以下での定期取得、追加USB保存、毎日の手動作業の要求。

継続運用の担当や頻度、保存先の選定はv0.20.0の進行条件にしない。既存の確認済みコピー、鍵予備、試験結果は保持する。

## 後続版へ引き継ぐ方針

- 継続運用は商用環境だけを対象とし、自動化を前提とする。
- 台帳・参照証跡に更新がなければ、同一内容のコピーの反復取得は不要。
- 削除確定だけでなく、処理開始/中止、後処理、法的保全等の更新も対象とする。
- 保全先は商用サーバーと障害を共有しない場所とする。国内固定は不要・低コスト優先。
- R2は検討時点の第一候補にすぎず、未契約・未採用。実利用と管理画面の構成が定まった時点で再評価する。
- 以前の保存済み版の保持、台帳消去・DB復元・公開再開の確認は、反復取得の要否とは区別する。

詳細設計の初期案は一時調査記録として保管した。価格や構成を採用済みとは扱わず、今は具体化を進めない。

これらは単発の実装・安全性検証で、継続運用の開始や商用リリース承認を意味しない。追加のステージングZIPのUSB保存は不要。

v0.20.0は規約・同意機能等の残りの実装・受入と、通常のリリース判定へ進む。既存のDB保護、バックアップ、暗号化、削除処理の安全性確認まで一括して延期したとは解釈しない。
