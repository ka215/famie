# F03：運用通知メール1通の送信・受信を確認する

2026-11-06作成。同日、運営者が「送信OK／受信トレイに到着／staging」と報告し、ステージングの既存運用通知先へのテスト通知1通の送受信確認が完了した。アシスタントによる追加送信・設定変更は行っていない。

確認範囲は既存候補のテスト通知経路。supportからの返信の迷惑メール判定、未配置F03処理の実通知、異常検知・重複抑止・復旧通知、商用運用の合格とは分ける。

今回の対象はステージングの既存の運用通知先です。supportメールの送受信確認とは別です。既存宛先を受信できることを運営者が確認してから、テストメールを1通だけ送ります。宛先・SMTP設定・cronは変更しません。

## 1. 受信するメールボックスを確認する

アシスタントが既存の設定キャッシュを読み取り、対象がステージング、監視が有効、運用通知先がメール形式として有効、送信方式がSMTPであることを確認しました。通知先は先頭が `a` の `famie.co` アドレスです。宛先全文・SMTP認証情報は文書に記録しません。

このメールボックスを受信できると確認できるまでは、手順2を実行しません。どのアドレスか分からない場合は、その旨を連絡してください。宛先を推測して送ったり、supportへ書き換えたりしないでください。

## 2. 開発PCからテストメールを1通送る

受信先確認後、開発PCのPowerShell 7で次の枠をまとめて実行します。USB・別PCでの操作は不要です。管理者起動も不要です。

```powershell
& {
    $ErrorActionPreference = 'Stop'
    if ($PSVersionTable.PSVersion -lt [version]'7.2') { throw 'PowerShell 7.2以上で実行してください。' }
    ssh -o BatchMode=yes -o ConnectTimeout=10 s140.coreserver.jp '/usr/bin/timeout --kill-after=5 45 /usr/local/bin/php84cli "$HOME/famie-stg/backend/artisan" famie:monitor-internal --test-notification --no-interaction'
    if ($LASTEXITCODE -ne 0) {
        throw '送信コマンドが失敗、または時間切れになりました。届いている可能性もあるため再送せず連絡してください。'
    }
    Write-Host 'テスト通知の送信処理OK。メール受信を確認してください。'
}
```

`テスト通知の送信処理OK` と出れば、送信コマンドは成功です。この表示だけでは受信完了とはしません。コマンドが失敗した場合も、SMTP受付後に応答が失われた可能性があるため、勝手に繰り返しません。

ステージングに配置済みのコードで、`--test-notification`が通常監視より前に分岐し、テスト通知だけを送ることを読み取り確認しています。通常監視・障害状態更新・backup prune・DBの初期化やマイグレーションは実行しません。送信失敗時には既存の私有運用ログへ失敗が記録される場合があります。`--test-notification`を外した別コマンド、scheduler、backup、cleanupは実行しないでください。

## 3. メールの到着を確認する

既存の運用通知先の受信トレイと迷惑メールフォルダーを確認してください。

| 確認項目 | 期待する内容 |
| --- | --- |
| 件名 | `Famie operations: test` |
| 本文の環境 | `staging` |
| 種別 | `test`。チェック名が `database` でも実際のDB障害を意味しない |
| 添付 | なし |

到着しない場合は5分ほど待ち、受信トレイ・迷惑メールの両方を再確認してください。その間、再送はしません。

次の3点をチャットで知らせてください。本文全文・ヘッダー全文・メールアドレス・認証情報は不要です。

```text
送信処理：OK／エラー
到着：受信トレイ／迷惑メール／5分待っても未着
本文の環境：staging／別の表示／未着のため不明
```

迷惑メールへ届いた場合、送信経路の疎通は確認できても、安定した通知受信は未完了として扱います。未着・迷惑メールの際の次の調査は結果を見て案内します。DNSやSMTP設定を自分で変更する必要はありません。

この確認はステージングから既存宛先へのテスト通知1通だけです。未配置のF03処理の実通知、異常検知・重複抑止・復旧通知、毎時運用、商用環境の確認は別です。架空の障害を実DBへ作ることはしません。
